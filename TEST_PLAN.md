# План тестирования Telegram бота для приема показаний счетчиков воды

## Обзор

Данный план описывает стратегию тестирования Telegram бота, разработанного с использованием библиотеки grammy. Бот предназначен для приема показаний счетчиков воды от пользователей ЖСК Западный г. Москва.

## Архитектура приложения

- **Фронтенд**: Telegram интерфейс (через API)
- **Бэкенд**: Node.js приложение на библиотеке grammy
- **База данных**: MongoDB (через Mongoose)
- **Контейнеризация**: Docker с многоступенчатой сборкой
- **Оркестрация**: docker-compose

## Стратегия тестирования

### 1. Функциональное тестирование бота

#### 1.1. Проверка обработки команд

##### 1.1. Команда `/start`
- **Описание**: Проверка корректной обработки команды /start
- **Ожидаемый результат**: 
  - При первом запуске создается запись пользователя в базе данных
  - Отправляется приветственное сообщение с инструкциями
  - При повторном запуске для зарегистрированного пользователя - только приветственное сообщение
- **Инструменты**: Jest с mocked Telegram API или библиотека grammy для тестирования
- **Сценарии**:
  - Новый пользователь
  - Существующий незарегистрированный пользователь
  - Существующий зарегистрированный пользователь
  - Пользователь с некорректными данными

##### 1.1.2. Команда `/register`
- **Описание**: Проверка регистрации пользователя в системе
- **Ожидаемый результат**: 
  - Статус пользователя изменяется на зарегистрированного
  - Устанавливается дата регистрации
 - Отправляется сообщение об успешной регистрации
- **Инструменты**: Jest с mocked Telegram API
- **Сценарии**:
  - Успешная регистрация
  - Повторная регистрация (пользователь уже зарегистрирован)
  - Попытка регистрации несуществующего пользователя

##### 1.1.3. Команда `/submit_readings`
- **Описание**: Проверка ввода показаний счетчиков
- **Ожидаемый результат**: 
  - Показания сохраняются в базе данных
  - Создается запись о показаниях с привязкой к пользователю
  - Отправляется подтверждение об успешном сохранении
- **Инструменты**: Jest с mocked Telegram API
- **Сценарии**:
  - Корректные показания (холодная и горячая вода)
  - Некорректный формат ввода
  - Отрицательные значения
  - Слишком большие значения
  - Отсутствие аргументов
  - Незарегистрированный пользователь

##### 1.1.4. Команда `/history`
- **Описание**: Проверка получения истории показаний
- **Ожидаемый результат**: 
  - Отображаются последние 10 записей показаний
  - Показания отсортированы по дате (новые первыми)
 - При отсутствии показаний - соответствующее сообщение
- **Инструменты**: Jest с mocked Telegram API
- **Сценарии**:
  - Пользователь с историей показаний
  - Пользователь без истории показаний
  - Незарегистрированный пользователь

##### 1.1.5. Команда `/help`
- **Описание**: Проверка наличия и обработки команды /help (если реализована)
- **Ожидаемый результат**: 
  - Отправка справочной информации о командах бота
- **Инструменты**: Jest с mocked Telegram API
- **Сценарии**:
  - Вызов команды /help

#### 1.2. Проверка валидации данных

##### 1.2.1. Валидация показаний счетчиков
- **Описание**: Проверка функции validateMeterReadings из src/validation.ts
- **Ожидаемый результат**:

  - NaN значения отклоняются
  - Слишком большие значения отклоняются
  - Корректные значения проходят валидацию
- **Инструменты**: Jest для unit тестирования

  - Отрицательные числа
  - NaN и нечисловые значения

##### 1.2.2. Валидация формата ввода показаний

- **Ожидаемый результат**: 
  - Корректный формат (два числа после команды) проходит валидацию
  - Некорректный формат отклоняется
- **Инструменты**: Jest для unit тестирования
- **Сценарии**:

  - Отсутствие аргументов

  - Слишком длинные поля отклоняются
  - Некорректный формат username отклоняется
- **Инструменты**: Jest для unit тестирования
